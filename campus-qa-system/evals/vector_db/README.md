# evals/vector_db — 检索层评测与拒答阈值标定

本目录是 **vector_db 组**的交付物，负责回答一个问题：**向量检索这一环，能不能撑住拒答。**

不测端到端。端到端答错时错因混了「检索没召回 / Prompt 没约束 / LLM 不听话」三段，
无法定位。本组只测「该命中的块有没有进 top-k」，并把分数分布交给编排层标定阈值。

---

## 文件

| 文件 | 作用 |
|---|---|
| `corpus/os_course.txt` | 语料：操作系统 3 章 23 节，3084 字。1.1–1.3 为**教师样例原文**，其余为公开教材通用知识整理（见文件头来源说明） |
| `eval_set.jsonl` | 评测集 40 条：in_scope 24 / out_of_scope 8 / adversarial 4 / vague 4；每条带 `expected` 字段标明期望行为 |
| `check_split.py` | 分块完整性检查（差分法），改动 `doc_parser` 后必跑 |
| `run_eval.py` | 跑检索，产出 `results_{split}.jsonl`；`heading` 与 `fixed` 两种分块对比 |
| `compare_retriever.py` | 薄封装一致性校验（`rag_retriever` 应与 `vector_store` 完全一致） |
| `calibrate.py` | 阈值标定，产出 `calibration_{split}.json` |
| `check_clarify_rule.py` | 校验「模糊题该澄清」判据（参考实现，qa 组可直接复制） |
| `results_*.jsonl` | 每题 top-1 分数、命中排名、OOV 比、top-3 明细 |
| `calibration_*.json` | 机器可读的阈值建议，供编排层直接读取 |

## 跑法

```bash
cd campus-qa-system
python evals/vector_db/check_split.py --mode heading  # 先验分块完整性
python evals/vector_db/check_split.py --mode fixed
python evals/vector_db/run_eval.py --split both       # 两种分块都跑并对比
python evals/vector_db/calibrate.py --split heading   # 标定
python evals/vector_db/calibrate.py --split fixed
python evals/vector_db/compare_retriever.py           # 薄封装一致性校验
python evals/vector_db/check_clarify_rule.py          # 澄清判据校验
```

零第三方依赖，纯标准库。

## 判定口径：三类，不是两类

`eval_set.jsonl` 每条的 `expected` 字段标明期望行为：

| expected | 含义 | 条数 |
|---|---|---|
| `answer` | 应作答 → 分数 ≥ τ 判对，否则漏答 | 27 |
| `refuse` | 应拒答 → 分数 < τ 判对，否则该拒未拒 | 12 |
| `clarify_ok` | **应澄清** → 既不判对也不判错，单列 | 1（q38） |

**判对率分母 = 总题数 − `clarify_ok` 条数 = 39。** 同时报严格口径（把 `clarify_ok` 记为误答）备查。

为什么要有第三类：`q38`「操作系统是怎么管理这些东西的？」的 top1=0.2483，
**高于**可答题 `q39` 的 0.2082。把它记成「误答」会误导调参（抬 τ 先误伤 q39 和 q17），
记成「判对」又是自欺。正确行为是追问「你指哪一部分」，所以单列。
判据与参考实现见 `check_clarify_rule.py`。

## 关键结论（2026-09-22 实测）

### 0. 分块完整性：两种模式、5 组参数全部通过

用 `difflib.SequenceMatcher` 差分检查原文是否被完整保留，**缺失片段 0**。

顺带修掉一个缺陷：原 `_split_raw` 用 `chunks.append(head.strip())`，
strip 会吃掉重叠区里的空白，使实际重叠少于 `chunk_overlap` 配置值
（配置 12 实测最小 9）。内容不丢，但跨块短语可能无法完整出现在任何单块中。已修。

### 1. 分块策略：标题切显著优于定长切

| 指标 | heading（标题切） | fixed（定长切） |
|---|---|---|
| 分块数 | 29 | 28 |
| Hit@1 | **88.9%** | 74.1% |
| Hit@3 | **92.6%** | 88.9% |
| MRR | **0.907** | 0.815 |

未召回：`fixed` 下 `q01`、`q07`、`q20`；`heading` 下 `q01`、`q40`。
**建议 `doc_parser` 在向量库链路上启用 `split_mode="heading"`。**

### 1b. ⚠️ 命中判定修过一个误报（值得知道）

原 `match()` 在标题前缀不匹配时会**退到 `must_terms`**（"词是否出现在正文里"）。
实测踩坑：`q40`「内存那一块。」的 top-1 是「1.4 进程控制块 PCB」，
只因该块正文里有"内存指针"三个字，就被判成命中了第 2 章 —— **Hit@1 虚高**。

已改为：**heading 模式下有标题就只按标题判，不再退到 `must_terms`**。
修正后 heading 的 Hit@1 由 92.6% 降到 88.9%，MRR 由 0.944 降到 0.907。
`fixed` 模式无标题可用，仍走 `must_terms`，故数值未变（该路径偏松，只用于相对比较）。

**教训**：正文提一句某词 ≠ 这一节在讲该主题。命中判定的宽松度直接决定指标真假。

### 2. 无关题可分，诱导题不可分

| 类别 | top-1 分数 |
|---|---|
| 库内最低分（`in_library=True`，27 条） | 0.208 |
| 严格 in_scope 最低分（24 条） | 0.243 |
| 无关题最高分 | 0.161 |
| 诱导题最高分 | **0.452** |
| 模糊题最高分 | 0.427 |

- 无关题（"明天天气""写段快排"）与语料零字面重叠，分数天然低 → 分隔带 **+0.047**，可分。
- 诱导题（"PCB 在 Linux 内核源码中对应哪个结构体"）与语料字面高度重叠，
  但语料没有问句真正要的东西 → 分数 **高于**应答题最低分，分隔带 **−0.243**。

**口径说明**：0.208 那条是 `q39`「调度相关的东西。」，属模糊题但标记为库内可答；
严格 in_scope 的最低分是 `q17`（分段和分页）= 0.243。
两个口径下分隔带分别为 **+0.047** 与 **+0.082**，标定取保守口径（+0.047）。

**这是字面向量的表达上限，调参解决不了。** 任何单一阈值都无法同时做到
「零漏答」与「拦下诱导题」。

### 3. 推荐阈值

| 分块模式 | 推荐 τ | 判对 | 漏答 | 无关题拒答率 | 诱导题拒答率 | 待澄清 |
|---|---|---|---|---|---|---|
| heading | **0.185** | 35/39 (89.7%) | 0 | 8/8 = **100%** | 0/4 = 0% | 1 |
| fixed | 0.182 | 35/39 (89.7%) | 0 | 8/8 = **100%** | 0/4 = 0% | 1 |

严格口径（把待澄清记为误答）：35/40 = 87.5%。

选择策略：**先在「零漏答」约束内挑，再最大化正确拒答。**
漏答直接损失准确率分子；误答只影响拒答率分母，而拒答率是硬条件 —— 两者代价不对等。

任务书硬性条件「库外拒答率 ≥70%」按 out_of_scope 口径已 100% 达标。

**实测：全局最优与零漏答口径重合（都是 35 条）** —— 说明当前题集下
没有「多判对但要多漏答」的余地，判对率上限被诱导题锁死，靠调 τ 无法再提升。

### 4. OOV 信号：语料扩大后区分度下降

`vector_store.analyze()` 输出 `oov_ratio`（问句实词中不在语料词表的单字占比）：

| 类别 | OOV 均值 | 最高 |
|---|---|---|
| in_scope | 0.03 | 0.12 |
| out_of_scope | **0.65** | 1.00 |
| adversarial | 0.14 | 0.19 |
| vague | 0.15 | 0.33 |

⚠️ **语料从 1 章扩到 3 章后，诱导题的 OOV 从 0.31 降到 0.14** ——
因为"毫秒""结构体"这类词被新语料吸收了。无关题仍可分（0.65 vs 0.03），
但诱导题与应答题的 OOV 差距被压缩，**OOV 的辅助价值随之减弱**。

实测作硬门槛收益仍为 +0 条，故**只作辅助提示，不设阈值**。

### 5. 薄封装一致性校验

`plugins/qa/retriever.py` 已改为薄封装（方案 C），内部转发给 `vector_store`。
`compare_retriever.py` 用于验证改造生效：

```
Hit@1  88.9% vs 88.9%
Hit@3  92.6% vs 92.6%
MRR    0.907 vs 0.907
[PASS] 两者完全一致 —— 薄封装生效
```

若两者出现不一致，说明有人恢复了旧实现，分数尺度会重新变得无上界。

改造前的对比数据（方案选择依据）见 `docs/vector_db交接文档.md` 第 7 节。

## 交接给编排层（qa 组）

`calibration_heading.json` 里的 `recommend.tau` 可直接读用。四个约束：

1. **τ 绑定分数尺度。** 换 embedding、改分块策略或换语料后必须重跑 `calibrate.py`，
   否则全拒或全不拒。
2. **诱导题要靠「答案可支撑性检查」拦，不是靠阈值。** 具体做法：检索到的块里
   是否真的含有问句所问的那个具体信息（数值 / 实现 / 步骤）。这属于编排层职责。
3. **拒答判定在调用 LLM 之前完成**，用硬约束，不要写进 Prompt 让 LLM 自己判断。
4. **模糊题分两种，不能一刀切。** 指向明确的（q37/q39/q40）应作答；
   指向不明、无法锚定章节的（q38）应追问澄清，不是拒答。判据与参考实现见
   `check_clarify_rule.py`。
