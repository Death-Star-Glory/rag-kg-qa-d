## 4. 核心约定（必读）

### 4.1 插件接口

实现 `base.sdk.Plugin`：

```python
from base.sdk.base import Plugin, PluginMeta

class MyPlugin(Plugin):
    meta = PluginMeta(name="doc_parser", group="file_mgmt", version="0.1.0")

    def initialize(self, config=None): ...
    def methods(self):            # RPC 可调方法列表
        return ["split"]
    def call(self, method, params):  # 分发
        if method == "split":
            return self.split(**params)
        raise KeyError(method)
```

- `meta.name` 必须与拓扑配置里 `plugins` 的键一致（RPC 前缀）。
- `call` 的返回值必须可 JSON 序列化。
- `initialize` 中读 `config`，不要在模块 import 时做重逻辑。

### 4.2 RPC 协议

- 端点：`POST {base_url}/rpc`
- Body：`{"id":"...", "method":"{plugin}.{method}", "params":{...}}`
- 成功：`{"id":"...", "result": ...}`
- 失败：`{"id":"...", "error":{"code":int,"message":"..."}}`

错误码：

| code | 含义 |
|------|------|
| -32600 | 非法 method（无插件前缀等） |
| -32601 | 插件不存在 |
| -32602 | 方法不存在 / 参数相关 KeyError |
| -32000 | 插件内部异常 |

辅助端点：`GET /health`、`GET /plugins`。

### 4.3 远程调用

```python
from base.rpc.client import RemotePluginProxy
from base.sdk.base import PluginMeta

parser = RemotePluginProxy("doc_parser", "http://127.0.0.1:8101",
                           meta=PluginMeta(name="doc_parser"))
parser.initialize()   # 会调 doc_parser.info
result = parser.call("split", {"text": "...", "filename": "a.md"})
```

编排层只依赖 `Plugin` 接口，**不要**在业务代码里写死 HTTP。

### 4.4 拓扑配置

`config/topology.yaml`：

```yaml
nodes:
  file_mgmt_node:
    group: file_mgmt
    host: 127.0.0.1
    port: 8101
    data_dir: data/file_mgmt
    plugins:
      doc_parser:
        entry: plugins.file_mgmt.doc_parser:DocParserPlugin
        config:
          chunk_size: 200
```

- `entry` 格式：`package.module:ClassName`（相对 `campus-qa-system/`）
- `config` 原样传入 `Plugin.initialize`
- 数据路径建议放在对应 `data_dir` 下，避免节点互写

## 6. 如何新增一个业务插件

1. 在 `plugins/<组>/` 下新建模块，继承 `Plugin`。
2. 实现 `initialize` / `methods` / `call`。
3. 在 `config/topology.yaml` 对应节点的 `plugins` 里加：
   ```yaml
   my_plugin:
     entry: plugins.file_mgmt.my_module:MyPlugin
     config: { ... }
   ```
4. `python -m base.node --node <节点名>` 启动。
5. 用 `RemotePluginProxy` 或 `smoke_base.py` 模式做 RPC 自检。
6. 跨组依赖：在 `initialize(config)` 里用 `RemotePluginProxy` 连其它节点，**地址写在 config**，不要写死在代码里。

### 建议实现顺序

1. **file_mgmt**：`file_store` → `doc_parser`（拆解）  
2. **vector_db**：`embedder` + `vector_store`（可先内存实现）  
3. **kg**：`kg_builder` / `kg_query`（可先内存图）  
4. **qa**：`retriever` 调远程 → `generator`（可先 mock LLM）

## 9. 待办与风险

| 项 | 说明 | 优先级 |
|----|------|--------|
| 文件管理插件落地 | 存储 + 拆解，RPC 化 | 高 |
| gateway 编排 | 读流水线配置，串 file_mgmt → vector_db → qa | 高 |
| 配置中远程地址 | plugins config 增加 `remote_url` 约定 | 中 |
| 依赖与环境 | 固定 `requirements.txt`（目前仅 fastapi/uvicorn/pyyaml） | 中 |
| 向量/KG 具体选型 | Chroma / Neo4j 可在插件内选用，基座不绑定 | 中 |
| 鉴权与多机部署 | 原型阶段可省略；课设演示可用本机多进程 | 低 |

**风险**

- 插件 `call` 返回非 JSON 对象会导致 RPC 失败 → 统一转 dict/list。
- Windows 路径与中文目录：数据请配置到 `campus-qa-system/data/...`。
- 多节点同时写同一 `data` 目录会冲突 → 严格按 `data_dir` 隔离。
