# 接手提示词（交给自己的 AI Agent 用）

> **怎么用**：把下面 `====` 之间的全部内容复制给你的 AI Agent（Claude Code / CodeBuddy / Cursor 等），
> 只需把第一句里「负责 qa 编排模块的组员」换成你自己的角色，其余原样粘贴即可。
>
> **为什么需要这份**：Agent 没有上下文，如果不告诉它「代码在 `vector-db` 分支」，
> 它 `git clone` 完会直接去 `main` 里找，然后告诉你「没找到这个模块」。
>
> **红线**：这份提示词让 Agent 只做**验收**（拉取、阅读、运行、汇报），
> **不允许改文件、提交、推送、merge**。需要动手改代码时另开一轮。

## 一、任务目标

仓库 `https://github.com/Death-Star-Glory/rag-kg-qa-d.git` 的 **`vector-db` 分支**上，
有一个已完成的「向量数据库模块」交付。你的目标是：

1. **拉取并定位**这份交付 —— 注意它在 `vector-db` 分支，**不在 `main`**
2. **阅读**交接文档，理解接口契约，以及我们这边（qa 组）的对接义务
3. **实际运行**验证脚本，确认交付真能跑、指标是真的 ——
   **不要只读文档就下结论，文档里的每个数字都要自己跑出来对照**
4. **产出**一份验收报告
5. **不要修改任何文件、不要 git add / commit / push / merge。** 这是验收，不是开发

## 三、需要执行的步骤与运行命令


> 所以**必须用装了依赖的那个解释器**运行这些脚本，不要一会儿用系统 python、
> 一会儿用虚拟环境的 python。全程统一用一个。

### 步骤 1：本地冒烟（零依赖，先跑这个）

```bash
python smoke_vector_db.py
```

**期望**：末行输出 `vector_db 冒烟通过`

## 五、完成后的汇报要点

汇报时按这个顺序讲，**先给结论、再给证据**：
