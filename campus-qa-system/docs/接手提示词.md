# 接手提示词（交给自己的 AI Agent 用）

> **怎么用**：把下面 `====` 之间的全部内容复制给你的 AI Agent，只把第一句里的角色换成你自己的。
>
> **这份提示词只做一件事**：让 Agent 先**搞清楚现状**（我们做了什么、结果如何、还缺什么），
> 然后**停下来问你要做哪个板块** —— 不包含验收步骤，也不让它自己开写代码。

## 一、怎么拿到并读懂这个项目

```bash
git clone https://github.com/Death-Star-Glory/rag-kg-qa-d.git
cd rag-kg-qa-d
git checkout vector-db
git branch --show-current        # 必须输出 vector-db
git log --oneline -3             # 能看到 vector_db 相关提交说明即可
```

⚠️ **必须执行 `git checkout vector-db`。** 这个仓库的**默认分支是 `master`**，
直接 clone 会停在 `master`，而本模块的内容全在 `vector-db` 分支上。

**判断依据只看 `git branch --show-current`** —— 输出 `vector-db` 才算对；
输出 `master` 或 `main` 都说明你切错了，先切分支再往下读。
（该分支仍在继续加提交，**不要拿某个具体 commit hash 当判断依据**，会过期。）

正式开发入口是 `campus-qa-system/` 目录（仓库根目录还有历史 demo，供对照，不要动）。

**读这 4 份**（都在 `campus-qa-system/docs/`）：

| 文件 | 读什么 |
|---|---|
| `vector_db交接文档.md` | **最先读**。我交付了什么、接口契约、组外改动报备、已知限制 |
| `交接文档.md` | §2 四组边界、§11 vector_db 速览（含 §11.8 接手路线）、§12 回退方案 |

| `vector_db设计文档.md` | 选读：设计取舍与已知限制，判断「为什么这么设计」时看 |

想跑一下验证的话（可选，不强制）：

```bash
cd campus-qa-system
python -m pip install -r requirements.txt
python smoke_vector_db.py                            # 零依赖，末行应输出「vector_db 冒烟通过」
python evals/vector_db/run_eval.py --split heading   # Hit@1 88.9% / Hit@3 92.6% / MRR 0.907
```

> **若报 `ModuleNotFoundError: No module named 'base'`**，先别急着判定交付有问题 —— 这是
> Git for Windows 在部分环境下 `checkout` 没把文件写全导致的。核对一下：
> ```bash
> find . -type f -not -path './.git/*' | wc -l   # 磁盘上实际文件数
> git ls-files | wc -l                            # git 认为应有的文件数
> ```
> **两个数不一致**时执行 `git restore .` 补齐，再重跑即可。**这不是交付缺文件。**

## 二、我们（向量数据库组）做了什么

我们负责的是 **`vector_db` 模块**（`vector_db_node`，端口 8102）。
**职责边界**：向量化、入库、相似检索。
**不负责**：解析文档（file_mgmt 组）、生成答案（qa 组）。

**新增的东西：**

1. `plugins/vector_db/embedder.py` —— 字符 n-gram 哈希向量（unigram + bigram，MD5 哈希到 4096 维），零第三方依赖
2. `plugins/vector_db/vector_store.py` —— 内存向量索引；混合打分 `score = 0.75 × cosine + 0.25 × 关键词覆盖率`，归一化到 `[0, 1]`
3. `evals/vector_db/` —— 语料（3 章 23 节 3084 字）+ 40 题评测集 + 评测 / 标定 / 校验脚本
4. `smoke_vector_db.py`（本地，零依赖）、`smoke_rpc_vector_db.py`（走基座 RPC）

**改了 3 个组外文件（需要知悉）：**

| 文件 | 改动 | 影响 |
|---|---|---|
| `config/topology.yaml` | 新增 `vector_db_node`(8102) 及两个插件 entry；给 `rag_retriever` 加 `vector_store_url` | ⚠️ **副作用：`qa_node` 必须先起 `vector_db_node`，否则 `qa_node` 直接启动失败**（报 `HTTPError 502`）。这是显式依赖，不是 bug |
| `plugins/file_mgmt/doc_parser.py` | 修复块间重叠不足；新增 `title` 切分模式（**默认关闭**） | 默认行为与改造前逐字节等价（已实测） |
| `plugins/qa/retriever.py` | 改为薄封装（方案 C），内部转发 `vector_store` | 对外接口不变，调用点无需改动 |

**未改** `gateway/app.py`：已实测不传后端也能跑（走本地兜底），不关本模块的事，按组内决定不动。

## 四、这个项目还缺什么

**A. vector_db 本模块的遗留**

- 语料是**公开教材整理版**（1.1–1.3 节是教师样例原文，其余 20 节自行整理，来源写在语料文件头部）。
  教师未再发放完整版；若后续拿到，按设计文档 §11 的四步重跑即可，脚本现成。
- 向量索引是**内存态**，节点重启即丢，**没有持久化**。demo 每次建图重建即可。
- 交付在 `vector-db` 分支，**PR #1 已创建**（目标 `main`），尚未 merge。
  ⚠️ 另外注意：仓库的**默认分支是 `master`**（比 `main` 新 1 个提交），
  组员在 GitHub 上打开仓库会落在 `master`，在 `master` 上**看不到本模块**。

**B. 需要下游（qa 组）配合的三件事**

1. **拒答判定**：用 `search()` 返回的 `score` 对 `τ = 0.185` 过闸 —— vector_db **不做**拒答判定
2. **澄清判定**：三态口径（作答 / 澄清 / 拒答），判据可直接复制 `check_clarify_rule.py`
3. **诱导题兜底**：分数拦不住诱导题，必须在编排层加一道「答案可支撑性检查」

**C. 整个项目还没做的板块**（按基座建议的实现顺序）

| # | 板块 | 负责节点 | 状态 |
|---|---|---|---|
| 1 | file_mgmt：`file_store` + `doc_parser` | `file_mgmt_node` 8101 | ⏳ 待落地 |
| 2 | vector_db：`embedder` + `vector_store` | `vector_db_node` 8102 | ✅ **已完成（我们）** |
| 3 | kg：`kg_builder` / `kg_query` | `kg_node` 8103 | ⏳ 待落地 |
| 4 | qa：`retriever`（已接）+ `generator`（待补） | `qa_node` 8104 | ⏳ 部分完成 |
| 5 | gateway 编排：串 `file_mgmt → vector_db → qa` | — | ⏳ 待落地 |

另有基座层面的中低优先级待办（配置远程地址约定、依赖固定、鉴权与多机部署），见 `交接文档.md` §9。
